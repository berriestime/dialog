# Диалог

[Открыть приложение](https://dialog-topaz.vercel.app/) · [Видео демонстрации](docs/demo.mp4)

Веб-приложение для отправки и получения текстовых сообщений в Telegram через GREEN-API. Выполнено как тестовое задание на React; Telegram выбран из разрешённых альтернатив MAX. Интерфейс оформлен по мотивам чата MAX.

Стек: React, TypeScript, Rsbuild, CSS. Запросы к GREEN-API выполняются из браузера; отдельный backend не требуется.

## Видео демонстрации

[Смотреть или скачать демонстрацию приложения](docs/demo.mp4).

## Требования

- Node.js 22.12 или новее и npm.
- Авторизованный Telegram-инстанс в [личном кабинете GREEN-API](https://console.green-api.com/).
- Данные инстанса: `apiUrl`, `idInstance`, `apiTokenInstance`.
- Второй аккаунт Telegram для проверки отправки и ответов.

## Локальный запуск

```bash
git clone https://github.com/berriestime/dialog.git
cd dialog
npm ci
npm run dev
```

Откройте адрес, который выведет сервер в терминале. По умолчанию — [http://localhost:3000](http://localhost:3000).

Создавать `.env` не нужно. Параметры инстанса вводятся в форме подключения приложения.

## Подготовка GREEN-API

1. Создайте инстанс **Telegram** в личном кабинете GREEN-API.
2. Авторизуйте его через QR-код: в Telegram на телефоне откройте **Настройки → Устройства → Подключить устройство** и отсканируйте QR из кабинета.
3. Дождитесь состояния `authorized`.
4. В настройках инстанса включите:
   - **Receive webhooks on incoming messages and files**;
   - **Receive webhooks on messages sent from phone**;
   - **Receive webhooks on messages sent from API**;
   - **Receive webhooks on sent messages statuses**.
5. Оставьте **Webhook Url** и **Webhook authorization header** пустыми и сохраните настройки. Приложение получает уведомления через HTTP API, поэтому внешний webhook-адрес не нужен.
6. Скопируйте из карточки инстанса `apiUrl`, `idInstance` и `apiTokenInstance`.

Подробнее: [подготовка Telegram-инстанса](https://green-api.com/telegram/docs/before-start/) и [получение уведомлений через HTTP API](https://green-api.com/telegram/docs/api/receiving/technology-http-api/).

## Как проверить приложение

1. Введите параметры инстанса на экране подключения.
2. Нажмите **Новый чат**, введите телефон получателя в международном формате, например `+79999999999`, и создайте чат.
3. Напишите сообщение и нажмите **Enter** или кнопку отправки. **Shift+Enter** добавляет перенос строки.
4. Откройте Telegram на аккаунте получателя, проверьте сообщение и ответьте на него.
5. Ответ появится в приложении. Входящие обрабатываются и для невыбранных чатов.
6. Создайте второй чат и проверьте переключение, отдельные истории и черновики.
7. Обновите страницу: вход, выбранный чат, история и черновики восстановятся.

Статус исходящего сообщения меняется по уведомлениям API: **В очереди → Доставлено → Прочитано**. Ошибки отправки также отображаются. До получения уведомления статус остаётся последним известным; принятие запроса API не подтверждает доставку.

В приложении доступны поиск по чатам, светлая и тёмная темы, выход из сеанса. Выход очищает данные приложения в этой вкладке, но не отключает Telegram-инстанс.

## Хранение данных и ограничения

- Учётные данные, сообщения, статусы и черновики хранятся в `sessionStorage`. Они доступны JavaScript-коду страницы. Не добавляйте токен в исходный код или репозиторий.
- Выбор темы хранится отдельно в `localStorage` и сохраняется после выхода.
- История ведётся с момента обработки сообщений приложением; полная история Telegram не загружается. Чтение сообщения в интерфейсе пока не отмечает его прочитанным в Telegram.
- Для одного инстанса используйте одну открытую вкладку приложения. Одновременная работа на localhost и опубликованном сайте может приводить к конкуренции за уведомления: очередь общая.
- Поиск получателя по номеру зависит от настроек приватности Telegram. Если сопоставить номер не удалось, входящее сообщение может создать отдельный чат по Telegram ID.
- На тарифе Telegram Developer действует квота чатов. Номер `phone@c.us` и внутренний `chatId` одного человека учитываются отдельно. Ошибка **HTTP 466** означает исчерпание квоты; удаление локальных чатов её не сбрасывает. [Ограничения тарифа](https://green-api.com/telegram/docs/about-tariffs/).

## Структура проекта

```text
src/
  app/
    App.tsx                    # сборка приложения и вход
    styles.css                 # базовые стили и палитры
    model/session.ts           # сохранение и проверка сеанса
    ui/ChatWorkspace.tsx       # общий экран и координация чатов
  features/
    auth/ui/                   # форма подключения
    chat/
      model/                   # типы, reducer, статусы, уведомления
      ui/                      # переписка, создание чата, стили
    theme/
      model/                   # выбор и сохранение темы
      ui/                      # переключатель темы
  shared/
    api/                       # клиент GREEN-API и параметры подключения
    lib/                       # общие проверки данных
    ui/                        # иконки
  index.tsx                    # точка входа React
docs/
  demo.mp4                     # демонстрация
```

Зависимости направлены от `app` к `features` и `shared`. `features` используют `shared`, а `shared` не зависит от остальных слоёв. Внутри функций `model` отвечает за данные и логику, `ui` — за отображение.
